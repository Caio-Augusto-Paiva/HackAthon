# Base de conhecimento `kb/` (Seção 2) — Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** pacote `kb/` que define o formato canônico da base (modelos Pydantic), analisa dependências, valida a base com os erros e avisos da Seção 2, converte base ↔ grafo bipartido sem perda e lê/grava versões imutáveis.

**Architecture:** `kb/` é pacote folha (não importa `engine`, `api` nem banco). `modelos` define os tipos; `analise` calcula camadas, dependências e ciclos; `validador` usa `analise` e devolve um relatório (nunca levanta exceção para base malformada); `grafo` converte 1:1; `carregador` grava `base/versoes/vNNNN.json` sem sobrescrever e só depois de validar. O motor (`engine/`, já implementado) consome `Base.model_dump(mode="json", exclude_none=True)`.

**Tech Stack:** Python ≥ 3.12, Pydantic 2, pytest, hypothesis. Ambiente em `.venv` (o `uv` não está instalado nesta máquina; `pyproject.toml` fica compatível com `uv sync`).

**Spec:** `docs/superpowers/specs/2026-10-20-anamnese-bovinos-design.md` — Seção 2 (formato, grafo, validação, casos) e Seção 5.1 camada 2 (testes de `tests/kb/`). Revisão do motor: `docs/revisoes/2026-10-21-revisao-motor.md`.

## Global Constraints

- Sem LLM, rede ou banco no `kb/`; determinístico.
- `cf` de regra ∈ [−0,99; +0,99]; `cf_minimo`/`cf_maximo` ∈ [0, 1], só sobre símbolo `doenca` ou `derivado`, no máximo um dos dois por condição.
- Operadores canônicos: `=`, `≠`, `<`, `≤`, `>`, `≥`, `em`. Na carga, `!=`, `<=`, `>=` viram `≠`, `≤`, `≥`.
- Forma canônica de "X = não" em booleano: `{op: "=", valor: true, negado: true}`; `op "="` com `valor: false` em booleano é erro.
- Defaults: `prioridade` 100 (`bandeira_vermelha`), 50 (`urgencia`), 10 (`evidencia`) quando ausente; `combinacao` = `mycin`; `status` = `suposicao_a_validar`; limiares `descarte` −0,2, `premissa` 0,2, `hipotese_relevante` 0,35, `exaustao` 0,60, `potencial` 0,70, `confirmacao` 0,80, `bloco_principal` 0,50, `bloco_diferencial` 0,20; `limite_dinamico` produtor 12, veterinário 25.
- Camadas: `pergunta`/`ficha` = 0, `derivado` = 1, `doenca` = 2, `urgencia` = 3. Regra lê só camadas abaixo da do símbolo que conclui.
- `sem_problema` é símbolo de urgência mas **nunca** conclusão de regra.
- Ids de símbolo: `^[a-z0-9_]+$`; ids de regra: `^[A-Za-z0-9_-]+$`; ids únicos no conjunto símbolos ∪ regras (são nós do mesmo grafo).
- Escrita de JSON: UTF-8, `ensure_ascii=False`, `indent=2`, chaves na ordem do modelo, `\n` final.
- Comandos: `.venv/Scripts/python -m pytest …` (Windows). A suíte do motor (`python -m unittest discover`) deve continuar verde.

## Review Focus

1. Base carregada pelo `kb` e repassada ao motor muda o comportamento por causa de defaults injetados (prioridade, combinação) → teste em Task 6 compara `engine.inferencia.inferir` com a base crua e com o `model_dump` do `kb`.
2. Editor manda operador ASCII (`!=`, `<=`, `>=`) → Task 1 normaliza na carga; teste.
3. JSON com tipo errado (cf `"0,7"`, `se` vazio, `meta` ausente) → `validar_dados` devolve relatório com problema `estrutura`, nunca exceção; teste em Task 4.
4. `ativa.json` aponta para versão inexistente ou arquivo de versão já existe → erro claro, nada sobrescrito; teste em Task 5.
5. Ordem das condições e das regras se perde na ida e volta do grafo → Task 3 preserva `ordem` nas arestas; teste de igualdade exata.

### Task 5: Repositório de versões

**Files:** Create `kb/carregador.py`, `tests/kb/test_carregador.py`

**Interfaces:**
- Consumes: `Base`, `Caso`, `carregar_base` (Task 1); `validar`, `Relatorio` (Task 4).
- Produces:
  - `class BaseInvalida(Exception)` com atributo `relatorio: Relatorio`.
